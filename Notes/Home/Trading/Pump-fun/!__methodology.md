
Η μεθοδολογία που ακολουθήσαμε δεν ήταν «βρίσκω ένα score και αγοράζω», αλλά **εκτίμηση τεσσάρων διαφορετικών πιθανοτήτων για το τι μπορεί να συμβεί μετά την απόφαση εισόδου**, χρησιμοποιώντας μόνο πληροφορία που είναι διαθέσιμη πολύ νωρίς.
## 1. Τι προσπαθούμε να προβλέψουμε
Για κάθε νέο mint, στο checkpoint των **30 ms**, το σύστημα υπολογίζει τέσσερις ανεξάρτητες πιθανότητες:

|Probability|Ερώτηση|
|---|---|
|`P(BE)`|Πόσο πιθανό είναι το mint να φτάσει τουλάχιστον break-even;|
|`P(+0.004)`|Πόσο πιθανό είναι να δώσει τουλάχιστον +0,004 SOL καθαρό κέρδος;|
|`P(+0.008)`|Πόσο πιθανό είναι να δώσει τουλάχιστον +0,008 SOL καθαρό κέρδος;|
|`P(dead)`|Πόσο πιθανό είναι να αποδειχθεί dead/flat mint;|
Το σημαντικό είναι ότι τα `+0.004` και `+0.008` είναι **net αποτελέσματα**, όχι απλή μεταβολή spot price.
Στο labeling έχουν ληφθεί υπόψη:
- buy size `0,075 SOL`,
- Pump.fun fee αγοράς,
- Pump.fun fee πώλησης,
- fixed transaction costs,
- curve price impact.
Άρα το μοντέλο εκπαιδεύτηκε πάνω σε οικονομικά αποτελέσματα που έχουν νόημα για τη συγκεκριμένη στρατηγική.

---
## 2. Γιατί χρησιμοποιούμε πολλές πιθανότητες και όχι ένα score
Ένα mint μπορεί π.χ. να έχει:
```
P(BE)       = 82%
P(+0.004)   = 70%
P(+0.008)   = 43%
P(dead)     = 3%
```
Αυτό είναι διαφορετικό από:
```
P(BE)       = 67%
P(+0.004)   = 64%
P(+0.008)   = 59%
P(dead)     = 7%
```
Το πρώτο έχει μεγάλη πιθανότητα να μην είναι ζημιογόνο, αλλά μικρότερη πιθανότητα μεγάλης κίνησης.
Το δεύτερο έχει χαμηλότερη γενική ασφάλεια, αλλά καλύτερη πιθανότητα να γίνει αρκετά μεγάλο winner.
Με ένα μοναδικό score αυτή η πληροφορία θα χανόταν.

---
## 3. Τι δεδομένα βλέπει το μοντέλο
Χρησιμοποιήσαμε μόνο πληροφορία που μπορεί να είναι διαθέσιμη έως το decision checkpoint.
Υπάρχουν δύο βασικές οικογένειες features.
### Yellowstone / curve κατάσταση
Πληροφορίες για την πραγματική κατάσταση του bonding curve:
- reserves,
- μεταβολές της curve,
- creator behaviour,
- αρχική δραστηριότητα,
- χρονικά χαρακτηριστικά.
Αυτά αποτελούσαν ουσιαστικά το αρχικό baseline model.
### Deshred intent πληροφορία
Προσθέσαμε πληροφορία που υπάρχει **πριν ακόμη επιβεβαιωθούν όλες οι συναλλαγές**:
- αριθμός buy intents,
- αριθμός sell intents,
- unique buyers,
- external buyers,
- creator buys/sells,
- `exact_quote` buys,
- intended SOL,
- πρόσφατα buys στα 100/250/1000 ms,
- buy inter-arrival times,
- buy acceleration,
- buy/sell ratio,
- concentration/top buyer share,
- χρόνος από τελευταίο buy/sell.
Η βασική ιδέα είναι:
> Το Yellowstone μας λέει τι έχει ήδη συμβεί.
> 
> ​
> 
> Το Deshred μάς δίνει πληροφορία για το τι προσπαθεί να συμβεί.
Αυτό έχει ιδιαίτερη αξία όταν η απόφαση πρέπει να παρθεί σε μόλις 30 ms.

---
## 4. Πώς αποδείξαμε ότι τα intents προσθέτουν πληροφορία
Δεν θεωρήσαμε αυτονόητο ότι τα Deshred intents βοηθούν.
Συγκρίναμε το ίδιο dataset με:
**Baseline**
```
Yellowstone / curve features
```
έναντι:
**Baseline + Intents**
```
Yellowstone / curve features
+
Deshred intent features
```
Στο ανεξάρτητο validation dataset είχαμε περίπου:

|Target|Baseline AUC|+ Intents|
|---|---|---|
|BE|0,805|**0,827**|
|+0.004|0,802|**0,821**|
|+0.008|0,802|**0,818**|
|Dead|0,927|**0,932**|
Άρα τα intents έδωσαν πραγματικό πρόσθετο predictive signal.
Το μεγαλύτερο πρακτικό όφελος δεν ήταν ότι μπορούμε να προβλέψουμε τέλεια τους winners.
Ήταν ότι μπορούμε να **απορρίψουμε πολύ αποτελεσματικά μεγάλο μέρος των κακών/dead mints**.

---
## 5. Πώς επιλέχθηκαν τα thresholds
Δεν επιλέξαμε αυθαίρετα:
```
65 / 60 / 50 / 10
```
Ούτε χρησιμοποιήσαμε το τελικό holdout για να τα προσαρμόσουμε.
Η διαδικασία ήταν:
**Training → Validation → Freeze → Holdout**
Στα training DBs εκπαιδεύτηκαν τα μοντέλα.
Στα validation DBs εξετάσαμε διαφορετικά probability thresholds και τον συμβιβασμό:
```
λιγότερα trades
       ↕
καλύτερη ποιότητα trades
```
Καταλήξαμε στον κανόνα:
```
P(BE)       >= 65%
P(+0.004)   >= 60%
P(+0.008)   >= 50%
P(dead)     <= 10%
```
και **παγώσαμε τον κανόνα πριν εξετάσουμε το τελικό αποτέλεσμα του intent model στο holdout**.
Αυτό είναι σημαντικό για να περιοριστεί το overfitting.

---
## 6. Τι συνέβη στο validation
Ο frozen κανόνας επέλεξε περίπου:
```
271 / 2.782 mints
≈ 9,7%
```
Στα επιλεγμένα:
```
Break-even     72,7%
>= +0.004      67,2%
>= +0.008      61,3%
Dead            0%
```
Άρα το σύστημα πετούσε περίπου το **90% των raw mints** και κρατούσε ένα πολύ καθαρότερο υποσύνολο.

---
## 7. Τι συνέβη στο επόμενο holdout
Στο επόμενο σύνολο:
```
2.899 valid raw mints
```
ο κανόνας επέλεξε:
```
203
≈ 7%
```
Η σύγκριση ήταν:

||Όλα τα raw|Selected|
|---|---|---|
|BE|45,5%|**71,9%**|
|≥ +0.004|40,3%|**67,0%**|
|≥ +0.008|36,6%|**65,0%**|
|Dead|34,6%|**0,5%**|
Αυτό είναι ουσιαστικά το σημαντικότερο αποτέλεσμα της μεθόδου.
Δεν ισχυριζόμαστε ότι:
> «Το μοντέλο ξέρει ποιο mint θα κάνει pump.»
Το αποτέλεσμα είναι περισσότερο:
> **Από έναν πληθυσμό όπου περίπου 1 στα 3 mints είναι dead, καταφέρνουμε να δημιουργήσουμε ένα μικρότερο υποσύνολο όπου τα dead είναι σχεδόν μηδενικά και περίπου 2 στα 3 έχουν τη δυνατότητα να φτάσουν σημαντικό net profit.**

---
## 8. Γιατί υπάρχει και `P(dead)`
Θεωρώ ότι είναι από τα σημαντικότερα κομμάτια της σχεδίασης.
Θα μπορούσαμε να αγοράζουμε μόνο βάσει:
```
P(+0.008) >= 50%
```
Αλλά ένα μοντέλο που εκτιμά την πιθανότητα μεγάλης ανόδου δεν είναι υποχρεωτικά το καλύτερο μοντέλο για την αναγνώριση των εντελώς αποτυχημένων mints.
Γι' αυτό χρησιμοποιούμε ξεχωριστό classifier:
```
P(dead) <= 10%
```
σαν **αρνητικό safety gate**.
Ουσιαστικά η απόφαση είναι:
```
Έχει αρκετή πιθανότητα να επιβιώσει;
AND
Έχει αρκετή πιθανότητα να βγάλει τα κόστη;
AND
Έχει αρκετή πιθανότητα για ουσιαστικό κέρδος;
AND
Δεν μοιάζει με dead mint;
```

---
## 9. Γιατί το `P(+0.008)` είναι μόνο 50%
Το 50% μπορεί αρχικά να φαίνεται χαμηλό.
Δεν απαιτούμε όμως κάθε trade να έχει >50% πιθανότητα να είναι winner με συμβατικό risk/reward.
Η exit strategy έχει **ασύμμετρη κατανομή αποτελεσμάτων**.
Τα simulations έδειξαν ότι:
- πολλά trades χάνουν,
- ο median trade μπορεί ακόμη και να είναι αρνητικός,
- αλλά οι μεγάλοι winners αντισταθμίζουν πολλές μικρότερες/μεσαίες απώλειες.
Επομένως αναζητούμε **positive expectancy**, όχι απαραίτητα υψηλό win rate.
Η probability filter είναι εργαλείο επιλογής του κατάλληλου πληθυσμού. Η τελική κερδοφορία προκύπτει από:
```
Entry selection
×
Exit policy
×
Execution
```
και όχι μόνο από το classification accuracy.

---
## 10. Γιατί checkpoint 30 ms
Ο στόχος είναι να υπάρχει αρκετή πληροφορία για prediction χωρίς να χαθεί το πλεονέκτημα της πολύ πρώιμης εισόδου.
Πολύ νωρίς:
```
λιγότερη πληροφορία
→ αδύναμο prediction
```
Πολύ αργά:
```
καλύτερη πληροφορία
→ χειρότερη entry price
→ περισσότερος ανταγωνισμός
```
Τα 30 ms χρησιμοποιούνται ως συμβιβασμός ανάμεσα στα δύο.
Και γι' αυτό τα raw intents είναι σημαντικά: προσθέτουν πληροφορία **πριν προλάβει όλη αυτή η δραστηριότητα να εμφανιστεί ως confirmed Yellowstone trades**.

---
## 11. Τι δεν κάνει το μοντέλο
Είναι σημαντικό και για την production υλοποίηση.
Το μοντέλο **δεν προβλέπει**:
- αν θα μπούμε στο slot N, N+1 ή N+2,
- την ακριβή entry price,
- το ακριβές sell slot,
- transaction inclusion,
- MEV/order positioning,
- μελλοντική συμπεριφορά συγκεκριμένων wallets.
Αυτά τα αντιμετωπίζουμε ως execution uncertainty.
Το predictive layer απαντά μόνο:
> **«Με βάση όσα γνωρίζω τώρα, αξίζει αυτό το mint να μπει στον πληθυσμό των trades που θα επιχειρήσω;»**

---
## 12. Η τελική αρχιτεκτονική
Άρα η λογική στο shadow/live γίνεται περίπου:
```
NEW MINT
   │
   ├─ συλλογή curve + intent information
   │
   ▼
30 ms checkpoint
   │
   ├─ feature vector
   │
   ├─ P(BE)
   ├─ P(+0.004)
   ├─ P(+0.008)
   └─ P(dead)
   │
   ▼
Frozen probability rule
   │
   ├─ FAIL → reject
   │
   └─ PASS
        │
        ▼
     execution
        │
        ▼
     exit policy
```
Το σημαντικότερο είναι ότι **το μοντέλο δεν αποφασίζει πώς θα γίνει το trade**. Αποφασίζει μόνο ποια mints αξίζουν να φτάσουν στο execution layer.
Έτσι έχουμε καθαρό διαχωρισμό ανάμεσα σε **selection**, **execution** και **exit management**, που μας επιτρέπει να αξιολογούμε και να αλλάζουμε το καθένα ανεξάρτητα.
